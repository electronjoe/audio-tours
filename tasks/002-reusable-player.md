# 002: Reusable player, separate from per-tour content

Status: todo · Priority: medium · Raised: 2026-11-02 (Hobart road test)

## Why

> Break the website source code out into a re-usable piece, separate from the per-drive
> content, to the extent it makes sense.

## Now

Most of the split already exists:

| Engine (shared) | Content (per tour) |
| --- | --- |
| `site/player/` (app.js, style.css, icons), `site/sw.js` | `site/<slug>/tour.json`, `site/<slug>/audio/` (generated by `tour publish`) |
| `src/audiotour/` (render, master, publish pipeline) | `tours/<slug>/` (tour.toml, route.json, source/) |

What still couples them:

- `site/hobart/index.html` and `site/hobart/manifest.webmanifest` are hand-written. A new tour
  means copying them by hand, and any later fix to the page markup has to be applied to every
  copy.
- `site/index.html` (the list of tours) is hand-edited.
- `tour.json` has no documented schema or version, so the player and the publisher can drift
  apart unnoticed.
- The pipeline still uses audiobook naming in places: `config.Book`, `BOOKS_DIR`, the `[book]`
  table in `tour.toml`, and `docs/script-format.md`, which still says "books/<slug>" and
  `uv run audiobook check`.

## Change

Keep a single repo: the engine and the tours change together, and a separate package adds
release overhead for no gain yet. Make the boundary explicit instead:

- Move the page markup to `site/player/tour.html` (a template) and the manifest to a template
  as well. `tour publish <slug>` writes `site/<slug>/index.html` and `manifest.webmanifest`
  from them, filling in the title, short name and theme colour from `tour.toml`.
- `tour publish` also regenerates `site/index.html` from every published `tour.json`
  (title, mode (drive or walk, see 007), stop count, total minutes).
- Add `"schema": 1` to `tour.json` and document the fields in `docs/tour-json.md`. The player
  refuses an unknown schema with a clear message.
- Rename `Book` to `Tour` and `[book]` to `[tour]` (accept `[book]` for one release), and fix
  the audiobook leftovers in `docs/script-format.md`.
- Optionally, `tour new <slug>` scaffolds `tours/<slug>/` (tour.toml skeleton,
  `source/working-draft.md` with the format header, and a `plan.md` following
  `docs/process/`).

## Acceptance

- [ ] Deleting `site/hobart/index.html` and the manifest, then running `uv run tour publish hobart`,
      recreates them, and the player works unchanged (`tests/player_drive.py` passes).
- [ ] A second, throwaway tour can be published with no hand-written files under `site/`.
- [ ] `site/index.html` lists both tours.
- [ ] `docs/tour-json.md` exists, and the player checks `schema`.
